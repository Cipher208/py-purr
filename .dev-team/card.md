# Карточка задачи
## Задача
Переводы строк в рабочем дереве не расходятся с git, и расхождение ловится тестом, а не обнаруживается на четвёртый раз вручную.
## Что меняем
`tests/test_line_endings.py` — новый тест: читает файлы, отслеживаемые git, и падает со списком, если в текстовом файле есть CRLF при объявленном `*.py text eol=lf` в `.gitattributes`. Плюс нормализация рабочего дерева: сейчас на диске **21** файл в CRLF, тогда как в git они лежат в LF — 7 `.py` (`purr/store.py`, `tools/crash_harness.py`, `tests/test_store.py`, `tests/test_event_bus.py` и три судьи в `.dev-team/`) и 14 `.md` (`CHANGELOG.md`, `README.md`, ADR и 11 в `.dev-team/archive/`). Первая редакция карточки говорила «7» — это была ошибка замера: я считал только `*.py`, а `.gitattributes` пинит `eol=lf` и для `*.md`. Репозиторий при этом консистентен — расходятся именно рабочие копии, поэтому `git status` чист и проблема невидима. Цена уже заплачена: строковые замены по `\n` в этих файлах трижды молча не срабатывали, а я трижды этого не замечал. Продукт не меняется: правка только в тестах и в рабочем дереве.

## Команда прогона
uv run --extra dev python -m pytest tests/test_line_endings.py -q
## Критерий приёмки
Команда возвращает `0` и печатает `passed`. Обе стороны обязательны: сейчас тест обязан **падать** со списком CRLF-файлов (красное — до нормализации), а после нормализации проходить. Третья сторона: если снова создать `.py` с CRLF и добавить его в git, тест обязан снова упасть и назвать этот файл — иначе он декоративный. Отдельно: тест не должен падать на бинарных файлах (`.png`, `.db`) и на файлах вне git.
