# Карточка задачи
## Задача
Режим `run-journal` отказывает, когда прогон фактически не состоялся: пустая база больше не выглядит зелёной.
## Что меняем
`tools/crash_harness.py` — в `cmd_run_journal` вердикт выносится только если ребёнок подтвердил хотя бы одну запись: иначе печатается `ПРОГОН НЕ СОСТОЯЛСЯ` и режим возвращает `1`. Раньше пустая база давала `gap 0` и `exit=0`, то есть прогон, умерший до первой записи, был неотличим от чистого. Такой же сторож у `run-journal-txn` уже был. Документация: `README.md` (там прямо написано, что у `run-journal` сторожа нет) и `CHANGELOG.md`.

## Команда прогона
uv run python .dev-team/judge_empty_run.py
## Критерий приёмки
Команда возвращает `0`, оба прогона `PASS`: пустой прогон (ребёнок не подтвердил ни одной записи) даёт `exit=1` и печатает `ПРОГОН НЕ СОСТОЯЛСЯ`; нормальный прогон даёт `exit=0` и этой строки не содержит. Обе стороны обязательны: сторож, который отказывает всегда, приёмку не проходит — контроль ловит.
