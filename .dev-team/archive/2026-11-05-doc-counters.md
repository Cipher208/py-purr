## Критерий приёмки
Команда возвращает `0` и печатает `провалено 0 из 4`. Судья на чистом Python (без pytest/ruff в импортах) САМ запускает `uv run --extra dev python -m pytest -q` подпроцессом, парсит фактическое число `N passed` и проверяет четыре вещи:
1. В `README.md` ровно одна строка о размере набора, и она содержит фактическое N, а не 202 или другое зашитое число (проверка по смыслу с обязательной непустотой файла).
2. В `FUTURE_PLAN.md` нет устаревших `44/44 passed` и `Tests: 44`, выдаваемых за текущее состояние: раздел Stats явно помечен как исторический снимок с датой 2026-07-24 и содержит оговорку, что число актуально на ту дату.
3. В `README.md` рядом с примером `CallbackError` явно названо, что повторный `send()` того же события вернёт `False`.
4. Оба документа непустые и полные: README содержит разделы Installation, Quick Tour и Replaying the journal; FUTURE_PLAN содержит Roadmap, Milestones, Open Questions. Пустой или обрезанный файл не проходит как «нет запрещённых фраз».

Обе стороны: сейчас судья падает, после правки проходит. Негативный контроль, каждая мутация даёт `exit=1` с названной причиной: вернуть «202 tests»; убрать пометку историчности из Stats; убрать фразу про `False`; подменить число в README на другое несовпадающее; опустошить README. Судья, который сравнивает с захардкоженным 226 и не запускает pytest, приёмку не проходит — проверяется мутацией «добавить один тест в клоне» (число должно измениться и судья обязан это заметить).

## Отчёт
**Сделано.** `README.md`: число тестов `202` → `226` (взято из фактического прогона), рядом с примером `CallbackError` явно названо, что повторный `send()` вернёт `False` — закрыто замечание 2 verdict-021. `FUTURE_PLAN.md`: разделы `Working` и `Stats` помечены историческим снимком на 2026-07-24 с оговоркой, что числа актуальны на ту дату; устаревшие `44/44 passed` и `Tests: 44` сохранены внутри помеченных разделов, а не выброшены. Диф 12 строк из 80, только два документа. Коммиты `96bbe59` (судья), `aa656bb` (документы), `4b36bba` (waiver), `cdb5bac` (карточка).

**Чем доказано.** Вердикт `ПРИНЯТО` — `.dev-team/verdict/verdict-022.md`, приёмщик Warder, 10 проверок, замечаний нет. Судья `.dev-team/judge_doc_counters.py` запускает pytest сам и парсит `N passed`, а не сверяет с константой: литерала `226` в нём нет, ключевая мутация с добавленным тестом дала `227 passed` и отбросила зашитое `226`. Видел и я своими прогонами: база `провалено 3 из 4`, exit=1; `accept-base~1` даёт `exit=2`, как записано в карточке; фикс и доки `0 из 4`, exit=0; гейт D `12 строк из 80`; гейт E с отрицательным контролем; `226 passed`, ruff чист, CRLF = 0. Приёмка отбросила подмену судьи и 8 мутаций.

**Что осталось НЕПРОВЕРЕННЫМ.** Команда прогона в свежем клоне при стандартном temp-корне в конце сессии упёрлась в ограничение песочницы: накопилось 343 каталога `pytest-of-*`, уборка заблокирована, pytest вернул 1 на teardown при всех 226 зелёных тестах. Причина установлена прямым прогоном; в начале сессии три свежих клона исполнили ту же команду с `226 passed`, а с `PYTEST_DEBUG_TEMPROOT` — `0 из 4`, exit=0. Это свойство среды, не дефект судьи. Также вне проверки: Python 3.12/3.13, coverage-gate 85%, CI вне локального uv, рендер Markdown на GitHub/PyPI, воспроизводимость `uv.lock` на другой машине.
