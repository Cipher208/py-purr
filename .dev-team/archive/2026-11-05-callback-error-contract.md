# Карточка задачи
## Задача
Вызывающий StateMachine получает правдивый сигнал: при исключении колбэка после зафиксированного перехода бросается публичный `CallbackError` с `committed=True`, а не исходное исключение колбэка.
## Что меняем
Решение владельца от 2026-11-05 (дословно приведено в `## Решение` ADR-002): **вариант 2 — «Явный сигнал о зафиксированном переходе»**.

- `purr/state_machine.py`: исключения из `on_exit`/`on_enter`, возникшие ПОСЛЕ успешного коммита, оборачиваются в `CallbackError(committed=True, callback=<имя>, __cause__=<исходное>)`. Ошибки записи (`_commit_state`) НЕ оборачиваются и по-прежнему пробрасываются как есть.
- `purr/__init__.py`: новый публичный экспорт `CallbackError`, `__all__` 24 -> 25.
- `tests/test_state_machine.py`: класс `TestStateMachineCallbackContract`. `README.md` с исполняемым примером и тест `tests/test_readme_contracts.py` делает Chisel в `accept-fix`; `CHANGELOG.md` (Breaking / Added / Fixed) пишет Scribe в `accept-docs`.

Контракт выбран вместо компенсирующего отката: живая проба Keel показала, что откат не отменяет побочный эффект колбэка, оставляет окно видимости `B` для второго процесса и не удаляет исходное событие `transition` из журнала.

Принятое ограничение владельца: сигнал существует, но вызывающий обязан прочитать `committed`; повторный `send()` после `CallbackError` по-прежнему вернёт `False`. Это явно помечается в отчёте как непроверенное поведение вызывающих.

## Критерий приёмки
Команда возвращает `0` и печатает `6 passed` — фактическое число тестов класса `TestStateMachineCallbackContract` из вывода Assay. Три прогона без разброса. Замороженные ассерты (вариант 2, по ADR-002 раздел «Вариант 2»):
1. `CallbackError` экспортируется из `purr` и присутствует в `__all__`; у него есть атрибут `committed is True` и имя упавшего колбэка; исходное исключение доступно в `__cause__`.
2. При падении `on_exit`: бросается `CallbackError` (не `ValueError`), `on_enter` не вызван, состояние и данные в памяти и БД уже `B`, событие `transition` в журнале — переход зафиксирован до сигнала.
3. При падении `on_enter`: тот же `CallbackError` с `committed=True`, оба колбэка вызваны, переход зафиксирован.
4. Ошибка записи (`_journal_emit` бросает) по-прежнему даёт исходное `RuntimeError`, а НЕ `CallbackError`; колбэки не вызваны; БД откатилась к `A` — 12 тестов `TestStateMachineRollback` остаются зелёными.
5. Штатный путь без исключений: `send` возвращает `True`, колбэки `[('exit','A'),('enter','B')]`, событие записано, `set_state` не даёт сигнала.
6. README-контракт: пример ловли `CallbackError` с чтением `committed` добавлен в README и исполняется тестом `tests/test_readme_contracts.py`; проверяется ПОЛНЫМ набором, а не карточной командой. Пример и его тест входят в `accept-fix` (иначе полный набор краснеет на фиксе), CHANGELOG пишет Scribe в `accept-docs`.

Обе стороны: на `accept-base` хотя бы один тест падает по делу с `AssertionError` на конкретном значении (фактически 3 красных из 6; прототип Vitruv оставлял тест `on_enter` зелёным на базе, а замороженный критерий требует сигнал для обоих колбэков), после правки все зелёные; полный набор `226 passed`. Негативный контроль: подмена теста на `assert True`, мутации реализации (не оборачивать колбэки; оборачивать ошибки записи; выставить `committed=False`) отбрасываются. Гейт D в режиме `контракт`: обновлённые тестовые файлы перечислены в границах, тесты нового контракта краснеют на `accept-base`.

## Отчёт
**Сделано.** По решению владельца «Второй вариант» (вариант 2 ADR-002) реализован публичный `CallbackError` с `committed=True`, именем колбэка в `callback` и исходным исключением в `__cause__`. Исключения из `on_exit`/`on_enter`, возникающие ПОСЛЕ успешного коммита, оборачиваются; ошибки записи из `_commit_state` не оборачиваются. `purr/__init__.py` экспортирует новый тип (`__all__` 24 → 25); README получил исполняемый пример с чтением `committed`; CHANGELOG — Breaking / Added / Fixed. Диф 88 строк из 200, 4 файла. Коммиты `a83e0e8` (6 тестов), `2bb6d40` (реализация), `81a0aeb` (CHANGELOG), `cff852a` (карточка и ADR).

**Выбор владельца записан дословно** в `## Решение` ADR-002 с датой 2026-11-05 и однострочным обоснованием. Перед выбором лид измерил живой пробой, почему компенсирующий откат (вариант 3) хуже: он не отменяет побочный эффект колбэка, оставляет окно, в котором второй процесс видит уже «отменённое» `B`, и не удаляет исходное событие `transition` из журнала.

**Чем доказано.** Вердикт `ПРИНЯТО` — `.dev-team/verdict/verdict-021.md`, приёмщик Warder, 13 проверок в клонах. Видел и я своими прогонами: база красная `3 failed, 3 passed` с `AssertionError`, `accept-base~1` даёт `exit=4`, как записано в карточке; фикс и доки `6 passed`; полный набор `226 passed`; гейт D `88 строк из 200` в режиме `контракт`; новый README-тест на базе падает `assert 0 == 1`; гейт E `CHANGELOG тронут` с отрицательным контролем; ruff чист, CRLF = 0. Приёмка отбросила подмену теста и четыре мутации реализации.

**Что осталось НЕПРОВЕРЕННЫМ.** Принятое владельцем ограничение варианта 2: сигнал существует, но вызывающий обязан прочитать `committed`; тот, кто проигнорирует его и повторит `send()`, получит `False` — поведение внешних вызывающих не измерялось. `BaseException` из колбэка (`KeyboardInterrupt`, `SystemExit`) обёрткой не ловится (гипотеза по ADR, не исполнялось). Вне проверки: конкурентная запись, отказ на `INSERT OR REPLACE`, сбой диска, другие ОС, `snapshot()`/`restore_snapshot()` при `CallbackError`, серия повторных `send()`, реальные потребители с `except ValueError`. Замечание Warder: README явно запрещает повторную отправку, но не называет возвращаемое значение `False` — это закроет следующая задача «привести README к факту».
