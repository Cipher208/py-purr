# Карточка задачи
## Задача
Уборка и полная очистка пишут событие на каждое удаление, чтобы журнал восстанавливал то же состояние, что и база.
## Что меняем
`purr/store.py` — `sweep()` и `flush()` удаляли строки сырым SQL без `_journal_emit`, поэтому реплей журнала оставлял удалённые ключи живыми. Правка: событие `delete` на каждый удалённый ключ в той же транзакции, сбой вставки откатывает всю уборку. Документация: `CHANGELOG.md`.

## Критерий приёмки
Команда возвращает `0`, все три проверки `PASS`: контроль (убирать нечего → ноль событий), `sweep()` (событие `delete` на истёкший ключ), `flush()` (событие `delete` на каждый удалённый). Обе стороны: на базе `sweep` и `flush` дают `FAIL` с пустым списком новых событий. Отдельно проверяется главное следствие: реплей журнала на чистую базу даёт тот же набор ключей, что и живая база.

## Отчёт
**Сделано.** `sweep()` и `flush()` пишут событие `delete` на каждый удалённый ключ в той же транзакции; сбой вставки откатывает всю уборку. Коммиты `2cb8601` (судья), `b521b67` (правка), `70592c0` (документация). Диф 42 строки из 60.

**Чем доказано.** Вердикт `ПРИНЯТО` — `.dev-team/verdict/verdict-009.md`, приёмщик Warder, шесть клонов, 11 проверок. Ключевое:
- база `2 провала из 3`, фикс и docs `0 из 3`, три прогона идентичны;
- обе мутации краснят судью поимённо — `sweep` без события валит только `sweep`, `flush` без события только `flush`;
- **главное следствие, а не факт событий:** реплей журнала на базе расходится (`['dead1','dead2','live']` против `['live']`), на фиксе и доках совпадает;
- откат проверен инжекцией отказа в `insert_in`: после неудачной уборки в базе не остаётся полуудалённых ключей;
- подмена судьи отброшена сверкой закоммиченного артефакта с базой;
- пробы `HOLDS 12, BROKEN 0`, 202 passed, ruff чист.

**Что осталось непроверенным.** Реплей сравнивался по набору ключей, не по значениям и не по TTL — TTL в событие `set` не пишется, восстановить его из журнала нечем; это ограничение журнала, а не правки. Производительность `flush()` на больших базах не мерилась: теперь на каждый ключ пишется событие. Усечение WAL на диске после `maintain()` не проверялось.

**Замечание о процессе.** Работа была сделана при отключённом эксперте — без приёмки. Долг закрыт этой карточкой: проверял не автор, в клонах, с мутациями. Правило, которое стоит помнить: если приёмки не было, работа считается незакрытой, даже когда все проверки зелёные.
